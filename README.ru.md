Компактный инструмент для локальной работы с JSON в одном HTML-файле. Просматривайте дерево и таблицы, исследуйте значения, редактируйте исходник и сравнивайте документы без сервера, установки и внешних библиотек.

Версия 4.1 основана на компактном интерфейсе 3.0 и добавляет фоновый разбор и сравнение, настраиваемый поиск, предупреждения Unicode и точное сравнение чисел.

Тёмная палитра вдохновлена инструментами разработчика, включая IntelliJ IDEA. Это независимый проект.

## Быстрый запуск

1. Сохраните `JSON-Inspector-4.1.html` на компьютер.
2. Откройте его в современном браузере.
3. Нажмите «Открыть», перетащите JSON-файл в окно или вставьте текст во вкладке «Исходник JSON» и нажмите «Применить».
4. Нажмите «Пример», чтобы посмотреть встроенный документ.
5. Для сравнения примените основной JSON, откройте JSON Diff и загрузите второй файл.

Сборка не нужна. Для использования приложения не требуются Node.js, Python, менеджер пакетов или локальный веб-сервер.

Приложение рассчитано на открытие локальной страницы `file://`. Фоновые операции требуют Web Worker, создаваемого из Blob URL. Если политика браузера блокирует его запуск, приложение показывает ошибку, а не переходит незаметно к синхронному разбору. Поведение локального файла нужно проверить в целевом браузере.

## Язык интерфейса

Нажмите EN для переключения на английский или RU для переключения на русский. Кнопка показывает язык, на который можно переключиться.

Начальный язык определяется настройкой браузера: русский для русскоязычной настройки, иначе английский. Переключение не переводит и не изменяет ключи, значения JSON и имена файлов. Языковые настройки и документы не записываются в хранилища браузера.

## Дерево, таблицы и инспектор

- Нажмите на значение в дереве, чтобы открыть инспектор.
- Кнопка ↗ открывает в таблице контейнер или родителя выбранного значения.
- В таблице нажимайте значения для просмотра конкретных узлов; ↗ рядом с контейнером позволяет перейти внутрь.
- Режим «Записи» объединяет свойства объектов в колонки. Отсутствующие свойства обозначаются `—`; JSON `null` остаётся значением.
- Режим «Пути» показывает конечные значения и пустые контейнеры под выбранным корнем таблицы.
- «К родителю» переводит к родительскому узлу.
- «Копировать путь» копирует канонический путь. «Копировать поддерево» копирует полный исходный JSON-фрагмент с сохранением числовых токенов.
- Длинный предпросмотр обрезается, но копирование использует полное значение.

Внутренний выбор узлов и связи с родителями используют числовые индексы, а не отображаемые пути.

## Поиск

Включите любую комбинацию областей «Ключи», «Значения» и «Пути». Области объединяются по ИЛИ: достаточно совпадения в одной включённой области. Дополнительный фильтр ограничивает результат одним типом узла.

«Точное совпадение» сравнивает запрос с отдельной областью поиска целиком. «Учитывать регистр» сохраняет различие регистра. Поиск буквальный, без регулярных выражений; регистронезависимый режим не реализует полное Unicode case folding.

Строки ищутся в декодированном виде, числа — по исходным токенам. Логические значения и null используют своё JSON-представление. Для объектов и массивов поиск по значению использует название типа, а не сериализованное поддерево.

Кнопки ↑ / ↓ перемещают между совпадениями. Поиск выполняется в основном потоке с небольшой задержкой после ввода, а не в Worker.

## Пути

Поддерживаемые формы:

```text
$
$.users[0].name
$["users"][0]["name"]
$["key.with.dot"]["hello world"]
```

Канонические пути используют ключи в JSON-кавычках. Точечная запись подходит для имён, похожих на идентификаторы. Для пробелов, пунктуации, Unicode и необычных имён используйте скобки с двойными кавычками.

Это не полноценный движок JSONPath. Не поддерживаются шаблоны, фильтры, рекурсивный спуск, срезы и исполняемые выражения. Повторяющиеся декодированные ключи отклоняются, поэтому канонические пути однозначны внутри применённого документа.

## JSON Diff

Сравниваются последний успешно применённый основной документ и отдельно загруженный второй документ. Чтобы сравнить изменения исходника, сначала нажмите «Применить».

| Статус | Значение |
| --- | --- |
| Добавлено | Узел есть только во втором документе |
| Удалено | Узел есть только в основном документе |
| Изменено | Отличается тип, значение или содержимое потомков |
| Без изменений | Узлы равны по выбранным правилам сравнения |

Изменения распространяются на родительские контейнеры. Счётчики включают контейнеры и считают узлы, а не независимые операции редактирования.

### Правила сравнения

- Свойства объектов сопоставляются по декодированным ключам; их порядок не учитывается.
- Массивы сопоставляются по индексам. Перемещения и сдвиги не распознаются как отдельные операции.
- Строки сравниваются по декодированному значению, а не записи escape-последовательностей.
- Пробелы форматирования не влияют на семантическое равенство.
- Повторяющиеся декодированные ключи отклоняются в обоих документах.

Второй файл сохраняется при повторном применении основного документа. Для пересчёта откройте вкладку Diff заново.

Используйте фильтр статуса, поиск и страницы. Нажатие на показанное значение копирует исходный JSON-фрагмент. Кнопка ↗ рядом со значением основного документа открывает соответствующий узел в дереве.

### Режимы сравнения чисел

| Режим | Поведение |
| --- | --- |
| Точное числовое значение | Нормализация десятичного коэффициента и экспоненты без преобразования в JavaScript Number |
| Исходная запись числа | Сравнение исходных токенов, включая форму записи и завершающие нули |

В режиме числового значения эквивалентные десятичная и экспоненциальная записи равны. Отдельный переключатель задаёт различие между отрицательным и положительным нулём в этом режиме. Режим исходной записи всегда сравнивает точное написание.

## Целостность данных

### Сохранение числовых токенов

Парсер хранит числа как текст. Форматирование, минификация и копирование сохраняют такие токены:

```json
{
  "largeId": 9007199254740993,
  "precise": 0.123456789012345678901,
  "negativeZero": -0,
  "largeExponent": 1e999
}
```

Точное сравнение использует нормализацию строк и экспоненты BigInt, не разворачивая большие экспоненты в десятичные строки. Другие инструменты всё равно могут не поддерживать точное представление этих чисел.

### Unicode и декодирование

Одиночные UTF-16-суррогаты вызывают предупреждения; исходные данные не исправляются и не нормализуются незаметно. Подробности предупреждения указывают начало соответствующего строкового токена в единицах UTF-16, считая с нуля, а не точную позицию каждого суррогата.

Некорректные escape-последовательности и неэкранированные управляющие символы считаются ошибками разбора. Файлы декодируются как UTF-8; некорректные байтовые последовательности отдельно не проверяются. Начальный BOM удаляется при открытии обоих файлов.

### Повторяющиеся ключи и некорректный ввод

Повторяющиеся декодированные ключи отклоняются, а не перезаписываются: `"a"` и `"\u0061"` считаются одинаковым ключом. Это намеренная политика приложения.

Поддерживается JSON, а не JSON5 или JSON Lines. Комментарии, завершающие запятые, NaN и Infinity отклоняются. Диагностика по возможности включает строку и колонку.

Ошибка разбора сохраняет последние применённые дерево, таблицы и статистику. В редакторе при этом может находиться более новый некорректный черновик.

### Применение — не сохранение

«Применить» обновляет представления, но не сохраняет файл. Предупреждения перед заменой и закрытием страницы помогают избежать потери данных с учётом ограничений диалогов браузера.

«Скачать» запрашивает экспорт, но приложение не может подтвердить завершение загрузки браузером. Проверьте, что файл сохранён. Исходный входной файл не редактируется на месте.

## Фоновая обработка

Разбор, форматирование, минификация и структурное сравнение выполняются в Web Worker. Одновременно активен один вычислительный запрос; новый отменяет предыдущий. Кнопка «Отменить» останавливает активную операцию.

Поиск, передача модели, подготовка списка контейнеров, подсветка и отрисовка DOM всё ещё требуют работы в основном потоке. Фоновая обработка не гарантирует полностью неблокирующий интерфейс.

## Приватность и безопасность

- Обработка локальная; приложение не выполняет сетевых запросов и не имеет зависимостей времени выполнения.
- Документы не сохраняются в localStorage, IndexedDB или cookies.
- Пользовательские значения вставляются текстовыми DOM-операциями, а не интерполяцией HTML.
- Поиск свойств использует Map. Пути не исполняются как код.
- CSP блокирует сетевые соединения, встроенные объекты и фреймы. Встроенные скрипты, стили и Blob Worker разрешены для автономной работы.
- Копирование и скачивание инициирует пользователь.

Локальная обработка не защищает от скомпрометированного браузера, расширений, операционной системы или изменённой копии HTML. Обращайтесь с буфером обмена и экспортированными файлами согласно своим требованиям.

## Проверки и совместимость

Во время разработки вычислительное ядро прошло 40 автоматических проверок: числовые токены, отрицательный ноль, экспоненты, пути, повторяющиеся ключи, Unicode, некорректный ввод, точное сравнение, изменения предков, массивы и документ с 10 000 значений.

Также проверены синтаксис JavaScript и статические ссылки на DOM-идентификаторы. Это проверки разработки, а не полноценное браузерное тестирование или гарантия корректности последующих изменений. Тесты использовали отдельную копию функций ядра, а не автоматически извлекали актуальный код HTML.

Полный браузерный прогон для этого выпуска не выполнен. Внешний вид, запуск Worker при действующей CSP, доступность, фокус, скачивание, перетаскивание файлов и системный буфер обмена требуют ручной проверки в браузере.

Межбраузерная сертификация и полная безопасность не заявляются.
